Askbase

You know the question. The database has the answer. Askbase writes the SQL.

For the person who owns the numbers but does not write SQL. Instead of sending the question to a developer and waiting, you get the table, the query behind it, and a sentence saying what was counted. The model is a file on your disk, so nothing leaves the computer. Free, no account.

Who it is for

Three people, and the application is built for the first one

  • Primary

    The analyst who does not write SQL

    You answer for the numbers in your area and know the subject better than anyone, but every query goes through a developer and comes back in an hour, or in a week. Marketing, finance, clinical administration, logistics, HR.

  • Second

    The data engineer

    SQL is not your problem. Somebody else's schema is: two hundred tables, columns named fl_act, no documentation, and the author has left. There is a terminal command for that: it returns the query rather than the answer, reads a question from a pipe, and exits with a code a script can branch on. From source for now, not in the .dmg.

  • The gatekeeper

    The DBA, and whoever signs off on security

    You ask the database nothing. You decide whether anyone may. There is a page for you on exactly what this runs against your data, and the SQL for a read-only role to copy.

Who it is not for: if you have no access to the database, Askbase will not help. It does not create access and it cannot ask on anyone else's behalf.

What you can ask

Questions like these, in the words you already use

No table names, no joins and no date functions. English and Russian both work, and the same question asked two ways should give the same answer.

  • How many new customers came from each region in September
  • The ten products with the highest revenue this year
  • Average order value by month, for last year
  • Which orders have gone unpaid for more than thirty days
  • How many patients were admitted to each department last quarter

And what it will not do. It cannot answer what the database does not hold, so "why did sales fall" is out of reach. It does not forecast. It cannot change anything: the connection is opened read-only and a parser refuses every statement that is not a single SELECT.

Three steps

Connect a database, ask in words, read the answer

There is nothing to model, nothing to configure and no query language to learn. One setup step comes first: the model is a 4.7 GB file you install once with Ollama. After that the first answer takes about a minute.

    read-only · checked

    Connect

    Drag in an SQLite file, or type the path to it. Version 0.1.1 reads SQLite; PostgreSQL is next and is not in this build.

What makes it different

On your disk. The application works with the Wi-Fi switched off.

A read-only role, and instructions in the prompt. Published research shows prompt wording is not a safety measure.
A read-only role, plus a parser. One SELECT only, no recursive CTEs, a row limit and a timeout.
Whether you can check the answer
A table, and usually the SQL.
The table, the SQL, and the assumptions in a plain sentence, including who was left out.

Status

In development, and this page says so

Askbase is being built in the open. Version 0.1.1 runs on macOS today, against SQLite files, with the model on your own disk. It is not signed with an Apple developer certificate yet, so the system asks you to allow it once; the install page shows where and says plainly what that warning means.
