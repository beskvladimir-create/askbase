Install · version 0.1.1 · macOS, Apple Silicon

Download Askbase, and let macOS open it the first time

The build is not signed with an Apple developer certificate yet, so macOS will refuse to open it until you allow it once. That takes two clicks, and this page shows exactly where. It also explains what the warning actually means, because a product that asks you to wave a security prompt away owes you that.

Download for macOS, 35 MB All releases

Take 0.1.1, not 0.1.0. The button above gives you 0.1.1. Release 0.1.0, which was the one here until today, does not answer questions at all: the answer never reached the window from the thread computing it, so the clock ran and nothing arrived. It was a defect in the application, not in your database or your model. It is fixed, and it is left on the releases page rather than deleted, because withdrawing a bad release quietly is how nobody learns it was bad.

The disk image is not signed, so check it before you open it: shasum -a 256 Askbase-0.1.1-macos-arm64.dmg must print 4fe81fe133911482436f4ede8e122230951bac62de5593df0fb34933034656f7.

Before it can answer anything

Askbase does not download a model and does not use a hosted one. It talks to a model already on your machine, over the loopback address, which is why it works with the network switched off. Install one with Ollama:

ollama pull hf.co/mradermacher/XiYanSQL-QwenCoder-7B-2504-GGUF:Q4_K_M

About 4.7 GB on disk. The first question after a launch takes around a minute while the model loads into memory, and the ones after it take a few seconds.

Opening it the first time

  1. Open the .dmg and drag Askbase into Applications.
  2. Launch it. macOS says the developer cannot be verified and offers only Done. That is expected.
  3. Open System Settings → Privacy & Security, scroll to the Security section, and press Open Anyway next to the line about Askbase.
  4. Launch it again and confirm. macOS remembers the decision; you will not be asked again.

What that warning means, honestly. It does not mean macOS found anything wrong with the application. It means nobody has paid Apple to vouch for it: signing and notarisation require a developer account, and this build has neither. So the system cannot tell you who made it or that it has not been altered since, and it declines to assume.

You are entitled to be suspicious of that. The checkable answer is that the source is published: every line of what the application does to your database is in the repository, including the read-only enforcement and the rule that refuses any connection beyond this machine. If you would rather not take the warning on faith, build it yourself from that source, below.

Or run it from source, with no warning at all

Four commands. You get the same application, built on your own machine, so there is nothing to trust and nothing to allow.

git clone https://github.com/beskvladimir-create/askbase
cd askbase/desktop
uv venv && uv pip install PySide6 sqlglot
.venv/bin/python -m askbase

This is also how to check the promise rather than believe it:

.venv/bin/python -m askbase --selftest

It tries to reach the outside world, expects to be refused, tries this machine, expects to get through, and exits 0 only if both held.

The same thing from the terminal

For anyone who would rather have the query than the answer. It wraps the engine the window uses, so the read-only connection, the safety check and the bounds are the same code; it does not need Qt, which is why it runs where the packaged application does not. It is not in the .dmg yet, so it comes from source:

git clone https://github.com/beskvladimir-create/askbase
cd askbase/desktop
uv venv && uv pip install -e .

askbase "how many customers came from each region in September" --db sales.sqlite
askbase "top ten customers by revenue" --db sales.sqlite --sql-only
echo "unpaid orders over 30 days" | askbase --db sales.sqlite --json | jq .sql

Exit codes are the contract, so a script can tell the cases apart: 0 an answer, 1 wrong usage, or the local model is absent or not answering, 2 the question produced nothing the read-only check would pass, 3 the database refused the query, could not be opened, or the query was stopped for running past the timeout. --csv writes the whole result rather than the rows shown, and --no-journal keeps the question out of the local journal.

When the warning will go away

When the build is signed and notarised, which needs an Apple developer account. Until then this page will keep saying so rather than pretending the step does not exist. An Intel build and a Windows build are not available either; the application is written to be portable, but each platform needs its own packaging and its own signing.
