# Участие в разработке

[English version](CONTRIBUTING.md)

Задачи и запросы на слияние приветствуются. Пишите по-русски или по-английски,
как вам удобнее.

Одно стоит знать заранее. Этот репозиторий выгружается из рабочего дерева, а
не разрабатывается прямо в нём, поэтому запрос на слияние применяется вручную,
а автор указывается в сообщении коммита. Это ограничение того, как сейчас
устроена работа, а не оценка вклада, и его планируется убрать.


## Подготовка

Две среды, потому что они нужны для разного. В первой зависимости бенчмарка,
во второй Qt.

```bash
uv venv && uv pip install -e '.[dev]'
cd desktop && uv venv && uv pip install PySide6 sqlglot pytest && cd ..
```

Чтобы запустить само приложение, нужна ещё модель на этой машине:

```bash
ollama pull hf.co/mradermacher/XiYanSQL-QwenCoder-7B-2504-GGUF:Q4_K_M
cd desktop && .venv/bin/python -m askbase
```


## Проверки

```bash
./scripts/test_all.sh          # 707 тестов, модель не нужна
.venv/bin/python -m ruff check .
python scripts/build_site.py --check
```

GitHub Actions прогоняет ровно эти три команды на каждый пуш и каждый запрос на
слияние, на Python 3.11 и 3.13:
[.github/workflows/tests.yml](.github/workflows/tests.yml). Запускайте их всё
равно сначала у себя. Красная сборка это более медленный способ узнать то же
самое, а 3.11 стоит в матрице потому, что эту версию обещает pyproject и
именно на ней никто не разрабатывает.

`test_all.sh` запускает все три набора не случайно. Если запустить только
первый, молча пропускаются все тесты интерфейса, и именно так окно, которое не
умело отвечать на вопрос, попало в собранный выпуск.


## Правила изменений

- **Изменение поведения приходит вместе с тестом, который падает до
  исправления.** Выпуск 0.1.0 не отвечал на вопросы вообще, и при этом 382
  теста были зелёными, потому что ни один из них не нажимал «Спросить» и не
  ждал результата. Тест, который не может упасть, хуже отсутствия теста: он
  сообщает о свойстве, которое никто не проверяет.
- **Числа на сайте не вписываются руками.** Наше собственное измерение
  пишется ссылкой вида `{=модель|набор|метрика}` и подставляется из `results/`
  при сборке. `scripts/build_site.py` останавливает сборку, если ссылку нечем
  подтвердить. Число из чужой статьи это проза, и рядом с ним стоит ссылка на
  источник.
- **Несостоявшийся прогон это не результат.** Если больше половины запросов не
  выполнились, сводка не записывается вовсе. Прогон, отозванный задним числом,
  переезжает в `results/void/` вместе с файлом, где написано почему. Удалять
  его молча нельзя.
- **Отложенный набор не для разработки.** Не подгоняйте ничего под вывод
  `src/nl2sql_app/holdout/` и не меняйте генератор молча: он воспроизводится
  побайтово, в этом весь его смысл.
- **Слой безопасности ослабляется только осознанно.** Изменение в
  `src/nl2sql_app/safety.py`, которое что-то разрешает, должно приходить с
  тестом, показывающим, что именно теперь разрешено и почему это безопасно.
- **Никаких настоящих данных в задачах.** Воспроизводите проблему на выдуманном
  файле SQLite. Если проблема в самой схеме, сначала переименуйте таблицы и
  столбцы.
